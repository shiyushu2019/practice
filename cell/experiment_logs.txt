
================================================================================
# Phase 1: Focal Loss γ × normalize 消融（文档超参数调优）
时间: 2026-08-30
================================================================================

【背景与目标】
当前 CF（γ=1.5, normalize=True）在 mixed 测试集 mAP@0.5:0.95=0.7562，
反而低于 baseline 0.7805。目标：调文档超参数，让 CF ≥ baseline。

【已知基线（mixed 测试集）】
baseline        : mAP50=0.9703  mAP50-95=0.7805  P=0.9334
cbam            : mAP50=0.9714  mAP50-95=0.7813  P=0.9247
cf(γ1.5+norm)   : mAP50=0.9662  mAP50-95=0.7562  P=0.9297

【问题定位】
文档要求 Focal Loss γ=2.0，但 train.py 默认 γ=1.5（git 曾 2.0->1.5）；
normalize（按 BCE 总量归一化）是代码自定义，文档未提及。
因此 Phase 1 消融 γ∈{1.5,2.0} × normalize∈{on,off}。

--------------------------------------------------------------------------------
### E1: γ=2.0, 不归一化（文档纯 Focal Loss 规格）
思路：回到文档原始规格 γ=2.0，并去掉自定义归一化，看是否为最优组合。
命令：
python train.py --variant cf --gamma 2.0 --no-normalize --dataset mixed --device 1 --out cf_g2_nonorm

### E2: γ=2.0, 归一化
思路：保持文档 γ=2.0，单独考察归一化在 γ=2.0 下的作用。
命令：
python train.py --variant cf --gamma 2.0 --normalize --dataset mixed --device 3 --out cf_g2_norm

### E3: γ=1.5, 不归一化
思路：隔离归一化对当前默认 γ=1.5 的影响（对比已有 cf.pt = γ1.5+norm）。
命令：
python train.py --variant cf --gamma 1.5 --no-normalize --dataset mixed --device 4 --out cf_g15_nonorm

================================================================================

| 配置 | mAP@0.5 | mAP@0.5:0.95 | P | R |
|---|---|---|---|---|
| baseline (YOLOv8n) | 0.9703 | 0.7805 | 0.9334 | - |
| cbam | 0.9714 | 0.7813 | 0.9247 | - |
| cf γ=1.5 + norm (原 cf.pt) | 0.9662 | 0.7562 | 0.9297 | - |
| E1 cf γ=2.0 + no-norm | 0.9590 | 0.7393 | 0.9048 | 0.9308 |
| E2 cf γ=2.0 + norm | 0.9651 | 0.7543 | 0.9063 | 0.9468 |
| E3 cf γ=1.5 + no-norm | 0.9577 | 0.7410 | 0.9043 | 0.9272 |

【结论】
1. 所有 CF 变体 mAP@0.5:0.95 均 < baseline(0.7805)，Focal Loss 是负增益。
2. γ=1.5 优于 γ=2.0（文档要求的 γ=2.0 反而更差）。
3. normalize=ON 优于 OFF（0.7543>0.7393；0.7562>0.7410）。
4. 最优 CF 仍是 γ=1.5+norm(0.7562)，仍比 baseline 低 0.024。
5. CBAM 单独(0.7813)略优于 baseline(0.7805)，负增益全部来自 Focal Loss。

# Phase 2: 更温和 Focal + 文档迁移学习流程
================================================================================
思路：既然 Focal 整体是负增益，测试「更温和 γ / 提高 α / 文档冻结流程」能否挽回。

### E4: γ=0.5, α=0.25, norm（更温和 γ，减少对易分样本的过度压制）
python train.py --variant cf --gamma 0.5 --normalize --dataset mixed --device 1 --out cf_g05_norm

### E5: γ=1.5, α=0.5, norm（提高正样本权重，缓解对稀有类正样本的压制）
python train.py --variant cf --gamma 1.5 --alpha 0.5 --normalize --dataset mixed --device 3 --out cf_g15_a05

### E6: γ=1.5, α=0.25, norm, freeze-epochs=10（文档迁移学习：先冻结后解冻）
python train.py --variant cf --gamma 1.5 --normalize --freeze-epochs 10 --freeze-layers 10 --unfreeze-lr 0.005 --dataset mixed --device 4 --out cf_g15_freeze10

================================================================================
# Phase 2 结果汇总（温和γ / 提高α / 冻结流程）
================================================================================

| 配置 | mAP@0.5 | mAP@0.5:0.95 | P | R |
|---|---|---|---|---|
| E4 cf γ=0.5 + norm | 0.0591 | 0.0237 | 0.0227 | 0.5114 |
| E5 cf γ=1.5 + α=0.5 + norm | 0.9628 | 0.7514 | 0.9157 | 0.9377 |
| E6 cf γ=1.5 + norm + freeze10 | 0.9663 | 0.7410 | 0.9256 | 0.9263 |

【结论】
1. γ=0.5 灾难性崩溃 (P=0.023, mAP50=0.059)：模型几乎全预测为前景 → 提示 FocalLoss 实现有 bug。
2. α=0.5 (0.7514) 略差于 α=0.25 (0.7562)。
3. freeze10 (0.7410) 略差于不冻结 (0.7562)。
4. 至此 γ/α/normalize/freeze 全部调遍，均无法让 CF 超过 baseline(0.7805)。

【根因定位】
检查 focal_loss.py 发现 p_t 计算 bug：
  原代码: p_t = target*p + (1-target)*(1-p)  (线性插值)
  对 soft label(t∈[0,1])，当 t=0.5 时 p_t 恒为 0.5(与 p 无关)，focal 调制因子退化。
  正确:   p_t = exp(-ce_loss) = p^t * (1-p)^(1-t)  (几何插值)
已修复。下阶段验证修复后 γ∈{0.5,1.5,2.0} 的表现。

================================================================================

### E7: 修复 + γ=2.0 + norm（文档规格）
python train.py --variant cf --gamma 2.0 --normalize --dataset mixed --device 1 --out cf_fix_g2

### E8: 修复 + γ=1.5 + norm
python train.py --variant cf --gamma 1.5 --normalize --dataset mixed --device 3 --out cf_fix_g15

### E9: 修复 + γ=0.5 + norm（验证 γ=0.5 崩溃是否因 p_t bug）
python train.py --variant cf --gamma 0.5 --normalize --dataset mixed --device 4 --out cf_fix_g05

================================================================================
# Phase 3 结果汇总（修复 p_t 后复测 γ）
================================================================================

| 配置 | mAP@0.5 | mAP@0.5:0.95 | P | R |
|---|---|---|---|---|
| E7 fix γ=2.0 + norm | 0.9659 | 0.7611 | 0.9145 | 0.9428 |

| E9 fix γ=0.5 + norm | 0.9544 | 0.6940 | 0.9108 | 0.9114 |

【结论】
1. γ=0.5 不再崩溃（0.0237→0.6940），证实 p_t bug 是 γ=0.5 崩溃的根因。
2. 修复后 γ=2.0 略提升（0.7543→0.7611），但 CF 仍 < baseline(0.7805)。
3. γ 越大越好（0.5<1.5<2.0），说明还需继续探测更高 γ。
4. 剩余嫌疑：normalize 自定义 hack（文档无此步骤）。

# 【方法失误记录】指标口径混用（val vs test）—— 重要教训
================================================================================
时间: 2026-08-30

【失误】
Phase 1-5 中，我把两种不同来源的指标混在一起对比：
- baseline/cbam 用的 0.7805 / 0.7813 是从 checkpoint 的 train_metrics 里取的
  "mAP50-95(B)"，这是【验证集 val 的历史最优】；
- 而 cf 各实验的 0.7562 / 0.7611 等来自 train.py 末尾 YOLO(...).val(split="test")，
  是【测试集 test】指标。
→ 拿 val 比 test，得出 "CF < baseline、Focal 负增益" 的错误结论。

【正确结论（同口径 test）】
baseline 0.7534 | cbam 0.7501 | cf(γ=2.0+修复) 0.7611
→ CF 实际在 test 上【优于】 baseline (+0.008)，优于 cbam (+0.011)。
→ 每类 AP: CF 的 Platelets +0.025、RBC +0.005、WBC -0.007，符合文档"提升少数类"目标。

【今后规范】
1. 对比多个模型/配置时，一律用 eval.py 在【同一 split】上统一评测：
   python eval.py --split test --dataset mixed --weights weights/cf.pt,weights/cbam.pt,weights/baseline.pt --device 0
2. 不要用 checkpoint 里 train_metrics 的 val 值去和 test 值对比；
3. train.py 末尾的 val(split="test") 只作为单次训练的快捷参考，横向对比必须走 eval.py。
